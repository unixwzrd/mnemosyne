# P3e: Cooperative Evidence-Bound Streaming

Base: P3d `55ed2b5`. `await evidence.stream(leases, producer, consumer, *, limits=None)` is an explicit async gate, not automatic provider integration, protected activation or an autonomous agent loop. The trusted producer receives a tuple of freshly authorized results and returns a native async generator of builtin text chunks. The trusted consumer is synchronous and returns `None`. Original documents are never fetched or persisted by this gate.

## Enforcement

Accept 1-32 unique payload-free leases sharing the exact scope, destination and lifecycle epoch. Reauthorize/reload every lease before producer creation, before requesting each chunk, periodically while waiting, immediately before consumer invocation and before success. Do not accept caller-cached payloads or an already running stream. A native-source lease supplies assertion metadata only, not original bytes. There is no authorization cache. Per-task context must match at producer entry and after its next-chunk await; the host verifier must separately resolve current participants/grants because child tasks inherit snapshots, not a live link to parent ContextVars.

Each multi-lease reload also compares the same connection's SQLite `data_version`, `schema_version` and `total_changes` before and after assembly, and refuses a replaced connection or open transaction. This detects external commits, local writes and schema changes during assembly; it is not a cross-process lock or an authorization cache. SQLite documents that [data-version comparisons are meaningful only on the same connection](https://sqlite.org/pragma.html#pragma_data_version), and local commits do not change that connection's data-version value.

`EvidenceStreamLimits` selects polling interval (default 50 ms, allowed 5 ms-1 s), total gate timeout (default 30 s, maximum 300 s), maximum forwarded chunks (1024, hard cap 4096), UTF-8 bytes per chunk (8192, hard cap 65536) and total forwarded bytes (1 MiB, hard cap 8 MiB). Bounds govern admitted output, not producer/native database allocations or operating-system scheduling. Refuse unsupported chunks and excess budgets before forwarding them; already emitted chunks cannot be retracted. No query, source text or chunk is written to logs or retained in a receipt. A successful frozen receipt records sensitive scope/destination/epoch and delivered counts, not payloads or remote acknowledgment.

Use `asyncio.wait` timeouts to recheck authority without cancelling each slow next-chunk operation. On refusal, producer error, total timeout or caller cancellation, cancel/drain the one pending next-chunk task and close the generator. Cleanup is shielded from repeat caller cancellation, while the original refusal/error/cancellation retains precedence. Clear completed payload-bearing frames through the existing guard. No retry or resume follows an ambiguous partial delivery. Native async-generator cleanup must cooperate with cancellation and finish; arbitrary blocking Python, cancellation-suppressing producers/verifiers, hostile in-process owners and transport-level hard termination are unsupported. Cleanup can outlast the admission deadline. This is not a real-time or sandbox guarantee. The caller must qualify its actual transport's cancellation contract before installing this gate there.

## Compatibility And Acceptance

Existing issue/resolve/deliver signatures, defaults and algorithms remain unchanged. Synchronous consumer validation/invocation becomes shared implementation between delivery and streaming, without relaxing its None-only contract. No schema, CLI, adapter, background task service or deployment is added. The stream function is lazy-imported, so ordinary calls do not load asyncio through it.

Use synthetic disposable stores and native async generators, event-controlled authority changes and a real ephemeral loopback transport. Test normal/empty streams, all input/limit bounds, mixed/forged leases, source/project scope, A/B/A task isolation, revocation before creation/during waiting/before consumption/after a prior chunk, changed native bytes, budget/timeout failures, callback/producer errors, repeated cancellation during cleanup, complete task/generator cleanup and payload-free receipts. Denied canaries must never reach producers or consumers. Compare fixed predecessor workloads and new stream controls; maintain the parallel change log, API documentation and explicit uncovered-path matrix. Actual providers, timing confidentiality, audit/export/sync, restore, remaining ordinary entry points, P4 and R1 remain separate gates.

Python's [task documentation](https://docs.python.org/3.10/library/asyncio-task.html) specifies cooperative cancellation, independent task context copies and `asyncio.wait` timeout behavior. Those boundaries are part of this contract rather than promises of forcible cancellation.

Errors retain their identity at the immediate `await evidence.stream(...)` boundary. The internal next-chunk task carries exceptions as data so Python 3.10 cannot replace a producer cancellation at that boundary. A caller-created task or `asyncio.run` may still replace cancellation exceptions or messages on Python 3.10; see [CPython #89553](https://github.com/python/cpython/issues/89553), fixed upstream in Python 3.11. Payload-frame clearing waits until the stream worker and cleanup tasks have fully unwound; clearing a still-suspended coroutine frame can terminate it on Python 3.10. Consumer/refusal/cancellation errors take precedence over cleanup errors, and both completed error paths are cleared. Tests assert the API boundary rather than promising different behavior from an outer Python task.
