# Resumable Owner-Mode Index Generations (S4a)

This optional contribution builds on the S3b bounded excerpt catalogue. It is an explicit owner-mode API, not protected ingestion, a retrieval index, an embedding cache, an adapter change or permission to fetch sources. No existing tables, legacy APIs, live stores or embedding identities change. Original documents and extraction output remain external. S4 remains incomplete until compatible embedding reuse and integration qualify separately.

## Interface And Defaults

`SourceIndexGenerations(existing_connection)` has no constructor side effects. `begin(source_key, generation_key, fingerprints)` registers an immutable ordered manifest of at most 128 unique S3a plan fingerprints for an already registered source group. Fingerprints may describe not-yet-written plans, computed by S3a admission; they are identities, not authorization. An exact retry of the same group/key/manifest resumes the existing generation, even after publication. A changed manifest under the same key refuses. There are at most 64 retained generations per group; this API does not delete history or reset retention. An explicitly empty manifest is allowed to represent removal of all selected evidence without deleting any underlying evidence.

`checkpoint(generation_id, fingerprint, state="completed", reason=None)` records one manifest item. States are `planned`, `completed`, `failed` or `excluded`. Completed requires an existing, validated S3b plan in the same group. Failed reasons are the fixed codes `unavailable`, `changed`, `invalid` and `interrupted`; excluded reasons are `not-selected`, `unsupported` and `awaiting-preparation`. Arbitrary text, paths or provider errors are not stored. Completed and excluded are terminal; failed items can be retried. Exact checkpoint retries do not duplicate rows. A durable plan write and checkpoint can share a caller-owned transaction: neither commits the other's pending work.

`get(generation_id)` and `current(source_key)` return immutable metadata snapshots including ordered item states, total/pending/completed/failed/excluded counts and `staging` or `published` state. Counts describe this manifest only, not complete source search coverage or embedding readiness. No source text is returned. Missing reads return `None` without creating schema. A recorded failure remains visible until explicitly retried; interruption does not mark pending items complete.

`publish(generation_id)` requires every item completed or explicitly excluded and atomically switches the group's current pointer. The pointer must still equal the parent captured at begin. A competing publication refuses rather than silently overwriting newer work; create a new generation key against the new parent. Publication retry is unchanged only if that generation is still current; an old published generation cannot be republished over its successor. Previous published generations and their membership remain readable. In this owner-mode catalogue, removal from the new membership is selective invalidation of selection only, not policy revocation, cache invalidation, deletion or automatic derivative regeneration.

## Storage And Failure Behavior

Three additive optional tables store generation metadata, manifests/checkpoints and the current pointer. No excerpt is copied. Old S3b readers/writers remain usable; generation membership cannot recycle S3b's lifetime budgets. Plans written before an interrupted checkpoint remain charged to those budgets even when not current. The generation API never writes extracted text and does not create moments, working memory, FTS or provider traces.

Schema shape, UTF-8 encoding, type/byte bounds, row limits, cross-group references, terminal states, manifest identity and dangling records are checked before use. Generation metadata is returned from SQL as bounded bytes and then strictly ASCII-decoded; malformed UTF-8 TEXT cannot enter sqlite3's decoder exception with its offending payload. Unknown, partial or shadowed schema and corrupt rows refuse without repair. This is an accidental-corruption/owner contract, not protection against an owner changing valid records consistently or issuing raw SQL. Reads validate the group's catalogue in the caller's snapshot; they are not freshness or protected-access attestations. Raw storage/locking failures remain explicit; this does not sanitize arbitrary errors in unchanged legacy APIs or caller connection hooks.

Writes reuse S3b's guarded `BEGIN IMMEDIATE`/savepoint ownership model and drain result rows. Receipts say `committed` only when this API owns and commits the transaction; caller-owned writes say `pending`. Exceptions, cancellation and failed publication attempt invocation-local rollback without closing the caller's connection. SQLite lock/permission failures remain explicit. A successful COMMIT with a lost acknowledgement may persist despite an error; inspect or retry the exact key rather than blindly creating a new generation. Killing an uncommitted writer leaves the previous committed current pointer usable. No constructor or read migrates an old database; explicit begin creates optional tables transactionally.

## Qualification Boundary

Use only synthetic stores and metadata. Prove interrupted staging, competing publishers, recovery after reopen, caller rollback, fixed coverage, missing/foreign evidence, exact retries and old S3b compatibility. This checkpoint does not complete S4, A13/A14, protected revocation, full-source lexical coverage, source-wide retention or P3/P4. The persisted current pointer is index selection, not protected-mode activation. Embedding reuse must separately bind exact text, model, dimensions, preprocessing and an authorized sharing domain; no existing cache is assumed safe by this contribution.
