# P3b: Indexed Lineage, Quarantine And Request Epochs

Status: downstream candidate, based on P1c `10d0819`. This is an opt-in catalog upgrade and explicit policy-API extension, not store-wide protected activation. Native ordinary BEAM, plugins, SDK/CLI/MCP/Hermes adapters, external caches and export/sync remain unsupported for protected operation until P4 qualification. No live migration or deployment is authorized.

## Schema And Upgrade

`PolicyLifecycle(PolicyStore(conn)).prepare()` explicitly upgrades an existing prepared v1 catalog to schema v2 in one transaction, preserving native rows and all policy identities. It adds exact lineage records/edges, indexed quarantine and a monotonic epoch, initially zero. It adds no original content. Unconfigured/v1 stores remain unchanged. A v2 marker with missing/incompatible lifecycle schema refuses; v1 with partial lifecycle objects also refuses, never silently repairs. Older explicit policy readers reject the v2 version rather than treating it as v1. This does not stop an older ordinary native client, so it is not protected activation or downgrade-complete storage. Restoring a prior whole database can restore old epochs; an external monotonic authority/restore contract remains required before protected restore is qualified.

## Owner-Mode Lifecycle Operations

`bind_derivative(child, parents)` accepts bounded native `PolicyRecordRef` values and reloads exact parent policies from this same domain, not model-supplied labels. Up to 128 unique, already-bound active parents support a fresh child binding. The existing P3a calculation derives the immutable policy, and child binding plus exact parent edges and receipt identity publish atomically. An identical completed retry is unchanged; a pre-bound child without matching lineage refuses. That fresh-child rule prevents cycles through this API. Different owners/tenants, missing/quarantined parents and conflicting manifests refuse. Graph size is bounded to 4096 derivative records. Native content must already exist; callers may put content creation and this operation in one owner-held transaction. This is a trusted owner operation, not a replacement for authenticated derivative/provider creation.

`quarantine(record, reason)` atomically marks the exact root binding and every transitive registered descendant, preserving native bytes and lineage. Reasons are a fixed content-free vocabulary (revoked, corrected, deleted). Quarantine is monotonic: no unquarantine/reset/reclassification API is supplied. Exact retry is unchanged and does not increase the epoch. New quarantine advances the epoch once; receipts state committed versus caller-pending ownership and expose no descendant content/count. The parent index supports traversal and the binding index excludes quarantined records before candidate limits, text/vector consumption or ranking. Descendants cannot be attached after a parent is quarantined.

## Trusted Epoch Contract

V2 reads/writes require a keyword-only `lifecycle_epoch` in the trusted host grant. A freshly authenticated host must obtain it from current independent authority, not a model argument or a caller's stale SQLite snapshot. It must equal the catalog epoch in the operation's snapshot. Missing/wrong epochs refuse; v1 grants remain unchanged and use no epoch. Hybrid scope pinning includes the epoch. Explicit reads recheck the trusted grant before candidate selection and before releasing results; supported paths reject a changed scope/context/epoch and discard completed failure-frame payloads. This is cooperative checkpoint authorization, not cancellation of blocked host verification or linearizable revocation after the final check. Already emitted text cannot be retracted.

Output provenance records the epoch for future cache/handle validation; it is not itself a reusable authorization token. External caches, queued provider submissions, streaming delivery, exported/synced artifacts and automatic maintenance must remain unavailable for protected use until their own invalidation/output gates pass. Source expansion retains its fresh per-phase checks; no resolver opens are introduced during ordinary recall. A trusted process with arbitrary raw SQLite access is not sandboxed by this API.

## Acceptance

Use disposable synthetic stores. Test atomic upgrade/reopen, interrupted DDL/marker/lineage/quarantine writes, exact retry, caller rollback, old explicit-reader refusal, torn schemas, fixed graph bounds, multi-parent/multi-generation propagation and no implicit reactivation. Denied-canary checks must cover direct IDs/candidates, lexical, float32/int8, hybrid, source metadata and authorized source expansion. Exercise stale host grants and caller WAL snapshots, epoch changes between branches/before release, malformed grants and completed failure-frame cleanup. Preserve native content, legacy v1 behavior, exact embedding identity/dimensions and upstream changelog. Run interpreter/package/adapter tests, predecessor benchmarks and new bounded graph/recall measurements. No unit-level pass promotes complete A10/A11/B8/V5/V6/V7 or protected readiness.
