# P2b: Indexed Project Selection

Status: provisional downstream increment on P2a `210d715aa2d614566817a8ade8ca9ee5d19cc66d`, not upstream-approved, activated or deployed. Membership is relevance metadata, never an access grant. The existing bank-level API and legacy storage/read behavior remain unchanged by default.

## Optional Catalog

`PolicyProjects(PolicyStore(connection))` never opens a database or creates schema in its constructor. Explicit `prepare()` requires the existing prepared policy domain and transactionally adds three versioned optional tables: `policy_project_state`, `policy_projects` and `policy_project_memberships`. Its domain must match the policy catalog. Unsupported, incomplete or differently shaped catalogs refuse without repair. Older P1/P2a catalogs need no migration for bank-wide reads. No original documents, native text, vectors or embedding identities are changed or copied.

Owner-only metadata operations `register(project_id, actor=...)`, `propose(kind, id, project_id, origin=..., actor=...)` and `confirm(kind, id, project_id, actor=...)` are explicit. Registration records its actor and UTC time. A proposal records the exact policy binding, known project, origin, assigning actor and UTC time; confirmation adds a confirming actor/time without overwriting the proposal. Unconfirmed proposals never participate in selection. Exact retries are idempotent; changed original provenance or a second conflicting confirmation refuses. Native parent/binding/project existence is required; no implicit binding, classification or confirmation occurs. `get_membership` is owner-mode metadata access, not a protected query. Labels have no wildcard semantics. Metadata asserted by these owner operations is not independent proof of identity, human review or sharing authorization.

The membership primary key is `(binding_id, project_id)`; `(project_id, confirmed_by, binding_id)` is an additional query index. A native binding has at most 256 memberships in this prototype. Removal, supersession, reclassification, participant-aware administration, source-asset memberships and lifecycle audit are not implemented here; P3 and the S track must address them. This initial catalog records original assignment and one confirmation, not a general event journal. Deleted native parents cannot be confirmed and never consume a result page. Git/schema preparation is not protected activation or compatible-client refusal.

## Explicit Query Intent And Trusted Grants

`PolicyReader.get(..., projects=...)` and `candidate_ids(..., projects=...)` add optional selection. Omitting the argument retains P2a bank-wide semantics, including its refusal of a nonempty bound context project set. Passing a collection selects exactly that union; it must be a subset of the original trusted `AccessContext.projects`. Empty explicitly means no projects/no results, never bank-wide fallback. Unregistered projects or selections outside trusted grants refuse with a content-free selection error; there is no automatic all-authorized mode or wildcard expansion.

Project mode requires `read:projects`, the existing explicit bank/destination and authenticated assurance, plus a fresh verifier call `verify_context(original_context, bank=..., destination=..., projects=frozenset(...))`. Query intent does not rewrite authenticated claims or their fingerprint. The host returns a `ProjectReadGrant` (the common P2a bank/domain/owner/tenant/fingerprint fields plus the exact selected project set). A bank-only grant cannot authorize project mode; a project grant cannot authorize bank-wide mode. Construction of either object is not authentication. The real host still must authenticate/intersect participants, verify current epochs, verify every selected project's authorization, and bind the consuming destination. No production transport verifier or automatic context promotion is supplied.

The optional project catalog must be prepared even for an empty explicit selection. In the same snapshot as policy validation, every selected project must be registered. Inside the metadata-only materialized relation, an indexed `EXISTS` requires confirmed membership in at least one selected project; all P2a classification, owner, tenant, compartment, audience, purpose and unsupported-overlay restrictions still apply. Membership never bypasses those restrictions. A shared record appears once, not once per selected project; a shared source does not propagate its memberships to project-specific conclusions. Native content, ordering and pagination remain downstream of both relevance and authorization. Candidate/direct results do not expose other project memberships.

Selected projects count toward the combined 900-label SQL parameter budget. Missing/mismatched catalogs, unavailable verifier decisions and schema errors do not become successful empty responses. Only a verified, supported empty selection yields no results. P2a's request-start freshness, preserved caller snapshots, owner-mode boundary and SQLite 3.35+ requirement still apply; linearizable revocation and actual BEAM/vector/lexical/graph/write-path enforcement remain outstanding. See the [P2a read contract](policy-read-contract.md).

## Acceptance

Use disposable synthetic data only. Cover registered projects without members, proposals/confirmation provenance, exact retries/conflicts, shared membership union/deduplication, separately scoped interpretations, every P2a restriction, empty/unknown/ungranted selection, wrong grant mode/fingerprint/selection, copied contexts, missing/incompatible optional schema, pre-pagination selection, indexes, denied SQL content evaluation, parameter bounds, native IDs, main-schema qualification, transaction ownership, interruption and concurrent retries. Verify old bank-only reads do not need the optional catalog and unchanged clients remain usable; that compatibility is not a protected-mode claim. Compare legacy and authorized-query results, timing, index size and provider activity against the accepted P2a checkpoint. No minimum-engine runtime qualification, full A/B scenario acceptance or formal overhead budget is inferred.
