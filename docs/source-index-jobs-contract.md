# Model-Bound Owner-Mode Index Jobs (S4c)

This dependent contribution connects S4a generation checkpoints with S4b exact embedding artifacts. It is an opt-in owner-mode orchestration API, not ordinary ingestion, a protected adapter, a real provider configuration, a source resolver or permission to activate policy-aware memory. Original/extracted documents remain external; jobs operate only on declared S3b plan fingerprints and bounded retained excerpts. Existing APIs, schemas and deployed configuration remain unchanged.

## Job Identity And Progress

`SourceIndexJobs(existing_connection)` constructs handles without schema changes. `begin(source_key, job_key, fingerprints, *, contract)` atomically registers an immutable S4a manifest and its explicit S4b `EmbeddingContract`. A deterministic internal generation key includes the source group, host-owned job key and complete embedding contract. Identical retries resume; changed fingerprints under that key refuse. A different model, dimensions, sharing domain or preprocessing contract creates a different generation even when evidence is unchanged. One additive optional table preserves that association; no vector/text copies are stored in it. S4a's 64-generation/128-item limits and S4b's lifetime vector/contract limits still apply.

`get(generation_id)` reports immutable job metadata and S4a planned/completed/failed/excluded coverage, without claiming embedding readiness. `exclude(generation_id, fingerprint, reason=...)` explicitly records a native terminal exclusion (`not-selected`, `unsupported` or `awaiting-preparation`); no implicit exclusion or invented success occurs. Missing source preparation does not block explicitly excluded material, and the report continues to show its excluded coverage. Caller-owned begin/exclude writes remain pending until their owner commits; reads never create optional schema.

## Explicit Execution And Publication

`run(generation_id, *, compute)` requires a supplied callback and refuses caller-owned transactions before any callback. It first rejects a known stale parent, then materializes each nonexcluded plan's excerpts under the recorded contract. Each completed plan is rechecked for both artifact validity and durable lineage before its checkpoint is committed. A callback runs outside SQLite transactions. Failed or cancelled work attempts a fixed-code failed checkpoint without storing provider error text, then rethrows the original exception. Storage failure may prevent that checkpoint; it is not turned into successful empty work. Completed artifacts remain available for retry, and partial writes do not switch the current pointer.

Final readiness verification and native generation publication share a short write transaction: all items must be completed or explicitly excluded, all completed excerpts must have exact matching artifacts and lineage, and the parent pointer must still match. Existing usable selection stays current on callback failure, interruption, invalid artifacts or competing publication. Exact successful retry uses existing artifacts and does not call compute again. Process death after a provider completed but before durable artifact persistence may repeat the external computation; this is not exactly-once inference or an unbounded retry loop.

`current(source_key)` returns an `embedding_ready=True` job only after rechecking the active job's contract, every completed plan, each artifact and its exact excerpt binding within one read snapshot. A legacy evidence-only generation returns `None`, never a falsely certified embedding index. The internal `embedding:` generation-key namespace is reserved: missing job metadata/table for such a generation refuses rather than downgrading to legacy or being silently reconstructed by begin. A job that an older owner API published before embeddings were ready refuses as `index-job-incomplete`. A caller cannot promote arbitrary generation metadata into readiness by setting a completion flag. This snapshot is not a forever-valid capability or linearizable policy-revocation guarantee; protected lifecycle remains P3/P4 work.

## Failure And Compatibility Boundaries

Job schema/type/byte/identity checks reuse the explicit UTF-8 owner catalogue and generation contracts. Partial/unknown schema, reserved temp objects, triggers/extra indexes, orphan job rows, changed contract identity and malformed metadata refuse without repair. No full extraction, model output, provider credentials or free-form diagnostic is written. S3/S4 native metadata/vector schemas remain unchanged. An application owning the database can still issue raw SQL; these APIs are not a sandbox or protected authorization boundary.

Qualification uses synthetic callbacks, disposable databases, exact compute counters and denied/missing readiness controls. It must cover interruption with a usable predecessor, restart/resume, one changed excerpt, changed model/dimensions/preprocessing, explicit exclusions, stale competing publication, caller transaction ownership, actual subprocess termination and old S4a publication attempts. Full A13/A14 still require real importer/provider/adapter and protected lifecycle qualification; an owner job is not deployment approval or a complete search index.
