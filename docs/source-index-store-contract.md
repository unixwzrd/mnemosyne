# Durable Owner-Mode Excerpts (S3b)

This dependent candidate adds durable accounting for the explicit S3 excerpt catalogue. It is not protected ingestion, a legacy migration, a general memory writer, full-source search or authorization. Native legacy ingestion remains unchanged and must not be routed through this API as a shortcut to protected activation. Source groups and alias relationships are asserted by a trusted owning application, never inferred from a model argument, conversation title or document classification.

## Registration And Identity

`SourceIndexStore(existing_sqlite_connection)` constructs a handle without DDL, commits or filesystem access. `register_source(source_key, source_locator, limits=ExcerptLimits())` explicitly creates optional schema and a fresh native reference-only document asset. It reuses native URL normalization and asset identity. A pre-existing native asset cannot be adopted unless this catalogue already registered it to the exact group; unknown prior retention is not assumed to be zero. The same trusted group key attaches further fresh aliases to the same lifetime budget. A locator already attached elsewhere refuses. Groups are immutable in identity and limits, and support at most 32 aliases. No source matching, fetching, discovery or automatic group merging occurs.

The existing MediaStore source-revision API then registers byte revisions against the returned asset ID. New group and alias writes preserve caller-owned transactions and report `pending` until the owner commits. An identical registration retry is `unchanged`; conflicting limits refuse. No old table is rewritten or migrated.

## Writes And Budgets

`write(source_key, source_revision_id, extracted_text, *, extraction_sha256, output_locator, spans)` always re-runs S3a admission against raw inputs and the persisted limits; it never trusts a constructed plan or fingerprint as authorization. The referenced native revision must belong to an asset registered in that group. A single transaction validates schema, native identity, known legacy state, existing catalogue records and cumulative limits before inserting plan metadata and excerpts. Each stored excerpt also has a SHA-256 over its exact UTF-8 bytes, checked on read to detect accidental equal-length content substitution; this is not attestation against a database owner who can change both text and digest. No original or full extraction is passed to SQL. The application writes only catalogue metadata and selected excerpts, not an additional summary, provider trace, blob, moment, working-memory, FTS or application-owned content sidecar.

Budgets count logical live catalogue text, not physical SQLite pages. SQLite databases, WAL/rollback journals and free pages may contain repeated allowed excerpt bytes. This API neither promises forensic erasure nor imposes a physical file-size quota. There is no deletion/reset API through which successive generations can silently recycle a source's budget; physical retention and revocation remain separate lifecycle work.

Per-source bytes and excerpt count include **every catalogue row** across aliases, byte revisions, extraction digests, overlapping/disjoint plans and retries. Distinct plans conservatively charge all their excerpt bytes even when text overlaps; there is no deduplication credit. A precisely identical fingerprint retry returns the original plan without another charge. On the first nonempty write, a lifetime byte ceiling is fixed to the smaller of the configured byte budget and one quarter of that extraction's UTF-8 size. Later nonempty writes may lower this ceiling, never raise it; a smaller revision refuses if prior retained content already exceeds its proposed lower ceiling. Reference-only plans retain no text and do not change that ceiling. There are at most 128 plans per group, including reference-only plans, to bound metadata accumulation. Limits cannot be raised or reset by registering another revision or alias.

The catalogue refuses known pre-existing or subsequently introduced legacy text: registered assets with moments, nonempty metadata or textual descriptive fields, or associated working-memory metadata are not treated as empty. This is a bounded owner-mode check, not a proof against arbitrary unstructured legacy copies, dishonest alias assertions, raw SQL or a malicious process owning the connection. The protected adapter/lifecycle work must block unsupported legacy writes before claiming source-wide enforcement. No classification default or policy inheritance is implemented here.

## Transactions And Recovery

Owned writes use `BEGIN IMMEDIATE` and a unique savepoint. Caller-owned transactions remain owned by their caller; receipts distinguish `committed` from `pending`. Failures attempt to roll back this invocation's work without committing unrelated caller changes. An error after COMMIT has actually succeeded cannot undo it; recover by inspecting the exact plan or retrying identical input, not by assuming absence. Competing connections serialize budget decisions or return an explicit SQLite failure rather than overbooking. `count_changes` result rows are drained before finalizing transactions. A killed uncommitted writer leaves no partial batch; exact retries do not duplicate retained excerpts.

Optional tables and indexes must match the declared schema; partial schemas, views, shadow objects, extra indexes and catalogue triggers refuse instead of being repaired. Read methods do not create schema. Owner-mode `usage(source_key)` and `get_plan(fingerprint)` return validated bounded records from the caller's current snapshot; they are not authorization, fresh source verification or permission to inject text into a model. On a supported UTF-8 database, missing catalogue reads return `None`.

Only a UTF-8 `main` database is supported by this catalogue. A read-only `PRAGMA main.encoding` check runs before catalogue creation or content projections; other encodings refuse with `unsupported-encoding`, without converting the database or changing legacy MediaStore APIs. SQLite's [TEXT-to-BLOB cast uses the database encoding](https://www.sqlite.org/lang_expr.html#castexpr), and [database encoding is separately configured](https://www.sqlite.org/pragma.html#pragma_encoding), so accepting UTF-16 without this precondition would not bound returned UTF-8 bytes correctly.

Corrupt-row projections use SQL type guards and UTF-8 byte-length limits before values reach Python; NUL-containing text is not bounded by SQLite's character `length()` alone. Valid bounded NUL/multibyte excerpts remain supported. This bounds returned Python payloads, not SQLite page I/O or its transient native allocations while evaluating a damaged database. Caller connection hooks and storage failures may themselves prevent cleanup; the handle does not close a connection owned by someone else.

## Acceptance Boundary

S3b can qualify durable retention inside its own catalogue and inspect disposable database/WAL state for omitted synthetic markers. Full B1 and S3 acceptance additionally require enforcement across other enabled writers, derivatives and sidecars. Resumable index generations, embedding reuse and selective invalidation remain S4; policy inheritance/revocation and adapter activation remain P3/P4. Source content, Vaults, private banks, embedding identity and deployed services remain unchanged. Original sources and complete extraction output stay external under the existing reference contract.
