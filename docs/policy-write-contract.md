# P2e: Explicit Atomic Memory Creation

Status: provisional downstream increment on P2d `a10dbf862f435e226eff9f753d1c4aa59739ca13`. This guards a new creation API, not legacy writes, general mutations, protected activation or deployment. Preparation and existing APIs retain their behavior.

## Host Contract

`PolicyWriter(PolicyStore(connection), bank=..., verify_context=...)` opens no database and creates no schema. `BeamMemory.create_authorized(content, writer=..., record_kind=..., record_id=..., destination=...)` delegates to `writer.create(beam, ...)`. The writer and BEAM must share the exact, exclusively used connection. Only working and episodic creation are accepted; IDs are explicit bounded opaque strings, not content-derived dedup keys. Content is nonblank, valid UTF-8 text up to 16,384 characters, without NUL, preserved exactly rather than sanitized or summarized. This is a per-memory input bound, not S3's aggregate/source-retention contract or permission to archive full documents.

Each call requires authenticated host-bound context, the exact bank/destination, matching conversation and explicit `create:working_memory` or `create:episodic_memory`. Project-restricted contexts refuse; this increment does not imply bank writes from project-only grants or create implicit memberships. The synchronous verifier receives `verify_context(context, bank=..., destination=..., intent=MemoryWriteIntent(...))`. The immutable intent fingerprints operation, native kind/ID, SHA-256 of exact UTF-8 input, character count and conversation. Digests are sensitive metadata, not anonymization; no intent or content is logged automatically.

The verifier must authenticate participants, intersect grants, check current epochs, resolve actual bank/domain and destination, and establish the policy of the input being stored. It returns `MemoryWriteGrant` bound to the exact context fingerprint, intent fingerprint, domain, bank, destination and decision ID, with an authoritative immutable `MemoryPolicy`. A constructed dataclass is not authentication. Wrong bindings deny; verifier exceptions become content-free `context_unavailable`, asynchronous results refuse, and unknown contexts never receive permissive defaults. The grant is not a signed credential and must not be accepted from a model or untrusted tool argument.

Only context-origin policy is supported: origin context/epoch must match, owner must be an effective principal, policy/version/vocabulary must match, unsupported overlays refuse, and classification/compartment/audience/purpose restrictions must be readable in the effective context. Tenant assignment is the trusted host's responsibility and is retained exactly. The context's clearance ceiling is **not** a source-classification floor: the host must not declassify input by guessing from clearance or by accepting model-proposed policy. This API does not independently derive policy from source parents, classify content, enforce multi-source inheritance or authorize reclassification; those are separate P3/adapter contracts. Native `author_id` uses the validated owner, `author_type` remains unspecified, and channel comes from trusted context (or its conversation), rather than mutable BEAM attribution fields.

## Transaction And Results

Method-owned work takes `BEGIN IMMEDIATE` through the existing catalog transaction helper before schema/conflict reads. Caller-owned work uses an operation savepoint, preserving caller ownership and its snapshot; deferred caller transactions can still encounter `BUSY_SNAPSHOT`. Prepared policy schema, supported native columns, actual FTS5 surface and the known target insert trigger are checked, not repaired. Missing/changed surfaces refuse. No automatic migration, reindex or vector-table requirement is introduced.

Insert the native row and immutable policy binding/terms in one transaction. Scope is always session, source is conversation, timestamp is UTC, and other native fields retain database defaults. Existing FTS triggers run atomically. Postconditions check stored native content/scope/attribution and exact policy before success. An occupied native ID or orphan binding refuses with the same content-free denial, without reading existing content, overwriting, upserting, deduplicating or treating identical input as success. Different IDs may contain identical input. Automatic retry after an uncertain commit is not supported; the host must resolve the receipt/authorized state rather than blindly resubmit.

`AuthorizedCreation` returns native ID/kind, bank/binding, decision/context/epoch, intent fingerprint and transaction state, but no content. State `committed` means this method owned and successfully finalized the transaction. State `pending` means the caller owns final commit/rollback; it is not a durable acceptance receipt. SQLite failure or interruption rolls back method-owned work or its nested operation savepoint where cleanup remains available. Cleanup refusals, persistent cancellation or catastrophic SQLite errors can require connection-owner recovery; no authorizer/progress handler is cleared, no caller transaction is committed on its behalf, and no power-loss durability claim is inferred from process-abort tests. Verification is at request start, not linearizable revocation at commit.

## Unsupported Side Effects And Qualification

No legacy `remember`, deduplication, automatic metadata classification, entity/fact extraction, provider/embedding call, trimming, sleep queue, cache invalidation or external event is invoked. New records have no vector until a separately authorized indexing path runs. Old hybrid/cache paths do not acquire parity or protection through these inserts. Native FTS derivatives are local to the same store; universal policy protection of derivatives/maintenance and activation still depend on P3/P4. Trusted database/extension/trigger owners remain inside the boundary; this is not a sandbox against arbitrary SQL or malicious schema replacement.

Qualify real disposable BEAM stores across both tiers, native/FTS/catalog atomicity, current request-bound grants, every restriction/refusal, no unauthorized row disclosure, conflict/replay, caller savepoints/commit states, lock/permission failures, interruption/recovery, cross-context dispatch and no enrichment/provider side effects. Compare the preceding accepted checkpoint's legacy workload and measure new creation throughput/footprint with correctness oracles. Keep actual full-document retention, source derivatives, general update/delete, project writes, adapter authentication and live memory acceptance explicitly unqualified.
