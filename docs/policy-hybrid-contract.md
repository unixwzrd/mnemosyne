# Explicit Authorized Hybrid Recall (P2f)

This dependent contribution exposes `BeamMemory.recall_authorized_hybrid(query, query_embedding, *, embedding_model, reader, destination, projects=None, top_k=20, candidate_limit=200, scan_limit=1000)`. It combines the qualified explicit P2c lexical and P2d float32 vector paths, not ordinary BEAM/polyphonic recall. Existing `recall`, graph/fact/temporal/canonical paths, native writes, provider calls and activation remain unchanged. The additive `PolicySurface.HYBRID` declaration is explicit; old clients must refuse an unknown surface, never reinterpret it as unrestricted BEAM.

## Authorization Before Each Consumer

The caller supplies a host-bound authenticated context and trusted PolicyReader. Required operations include read bank/projects plus `recall:hybrid`, `recall:lexical` and `recall:vector`; the conversation must match the BEAM instance. Query/vector/model/dimension and native schema requirements remain those of the explicit underlying paths. Unsupported vector formats, models, backends or contexts refuse the whole hybrid operation; there is no lexical-only or legacy fallback.

The initial trusted grant pins the context fingerprint and exact domain/bank/destination/owner/tenant/project scope. A separate reader forwards fresh host verification before each branch's SQL and refuses a changed scope or context before candidate materialization. It also rechecks between branches, before fusion and before release. Decision receipt IDs may change while scope remains identical. A mid-operation permission/participant/epoch/purpose change refuses rather than returning an earlier privileged branch. The public boundary catches BaseException only to clear completed worker/cause/context/group traceback frames using the existing qualified source-expansion cleanup helper, then rethrows the same exception; earlier branch hits must not remain in completed failure-frame locals. This is payload disposal, not error replacement or secure erasure. No denied pool is retrieved then post-filtered, and no model/reranker/provider sees intermediate results. This is cooperative freshness at explicit checkpoints, not linearizable revocation or cancellation of blocked verification; P3/P4 must qualify those broader guarantees.

Both branches share the caller's guarded read transaction/snapshot. If the caller already owns it, ownership and pending work remain unchanged; this does not make a stale caller snapshot a fresh policy database. The host owns current participant intersection and epochs. Per-branch eligible candidates are selected by indexed metadata before limits, content evaluation or scoring. Only those already-authorized hits enter fusion. Returned diagnostics count authorized/examined candidates, not denied objects or global corpus totals; timing confidentiality remains unqualified.

## Bounded Deterministic Fusion

Top-k is 1–100; candidate and vector scan limits are top-k through 1000. Each branch contributes at most top-k hits. Reciprocal-rank fusion uses the existing native convention `sum(1 / (60 + rank))`; it does not call the legacy polyphonic engine, whose identity deduplication/content hydration and extra voices are not protected. This small pure combiner keys by exact record kind and ID, so equal IDs in different tiers remain distinct. A record appearing in both branches must have identical binding, policy, context, content and truncation metadata or the operation refuses. It performs no global corpus ranking, cross-tier content deduplication, hidden query embedding or extra native read after fusion.

Results retain native policy/binding provenance, both branch ranks, fixed RRF score, model/dimension and the final fresh decision receipt. Sensitive result fields are excluded from representations. Legacy vector model provenance/quantized-format limitations remain P2d's explicit qualification gap; supplying a model name does not certify unknown historical vectors. This API must not be advertised as store-wide protected mode or a safe retrofit of ordinary adapters.

## Acceptance Boundary

Use real disposable FTS/vec0 tables, denied high-ranking distractors, exact ranking oracles, distinct tier IDs, project selection, fresh-scope changes before every branch/release, provider tripwires, caller transaction preservation and unsupported format/model failures. P2f qualifies only explicit authorized fusion. Remaining graph/canonical/ordinary entry-point enforcement, guarded updates, derivative lifecycle, persistent activation, adapter parity and R1 compact prompt assembly remain separate gates. No live data, reindexing, provider requests or deployment is authorized by this contribution.
