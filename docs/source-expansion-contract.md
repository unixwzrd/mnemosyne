# Authorized Exact-Byte Expansion (SP2)

## Scope And Interfaces

This additive downstream topic depends on accepted SP1 `f154deacf6c4579b8d4a747ec9368bb22c479743`. `SourceExpander(reader, authorize_source=trusted_callback).expand(revision_id, destination=..., max_bytes=65536)` returns verified transient bytes from one authorized source revision or a content-free refusal. It does not replace ordinary recall, add tools to any adapter, enable protected mode, migrate a store, create a resolver, or change the existing verifier. The host explicitly constructs the reader/callback and authenticates/intersects all applicable participants. Context records, intent/grant dataclasses and capability declarations do not authenticate their constructors.

Expansion requires all three context operations: `read:bank`, `read:source-revision` and `expand:source-revision`, with the existing SP1 bank/destination/domain/owner/tenant/audience/purpose/compartment constraints. A missing, denied, unbound or orphaned revision refuses without invoking the source-authority callback or source I/O. A memory citation, predecessor binding or historical verification journal entry grants nothing. Only exact `original-bytes` representation is supported; metadata accepted by the owner-mode revision API is not thereby eligible for byte expansion.

The fresh `SourceExpansionIntent` binds a random request ID, complete effective-context fingerprint, destination, exact authorized metadata/provenance and byte budget. The host callback receives `(context, intent=..., phase=...)` and returns a `SourceExpansionGrant` bound to that exact fingerprint and phase (`open`, `read`, `release`), plus its decision ID, locator and explicit resolver. Reusing a previous request's grant or the wrong phase refuses. The host must recheck current authority on every invocation, not treat the request fingerprint as a credential. The resolver object and locator must remain identical through a request; relocation between separate requests is permitted when independently authorized and expected bytes match.

The host, not model arguments, supplies the locator and resolver. There is no URI parameter on expand, registry lookup, global resolver fallback, HEAD/ETag shortcut, presign or provider call. The host's resolver must enforce filesystem roots, symlinks, network destinations, redirects, credentials and timeouts as applicable. This API does not supply or certify that confinement, and real file/network resolvers remain separate qualification gates. Inline data/javascript and malformed locators refuse. Unsupported resolver schemes do not fall back to another resolver.

## Single-Open Integrity And Bounds

The existing S2a verifier hashes a private snapshot of SP1-authorized revision metadata through a capturing resolver/stream. This structural adapter exposes only the existing revision-getter seam and does not issue unscoped MediaStore reads. The verifier's only open is the approved resolver's only open. The capturing stream retains the same exact builtin bytes objects that the verifier hashes, checks read sizes and rejects malformed/subclassed stream chunks. The result is copied from that bounded capture, its checksum and byte count are independently cross-checked, and a fresh release checkpoint must pass after the stream closes. No successful result is produced from a verified observation followed by a second open.

The default budget is 64 KiB, with a fixed 1 MiB maximum and a one-byte EOF lookahead. These are transient response/allocation limits, not the still-unreviewed S3 retained-excerpt or aggregate-indexing budgets. Known oversized sources refuse before external I/O; unknown-size sources stop at the bounded lookahead. There is no partial output, unverified streaming, range selection, automatic truncation, text decoding or source-understanding provider. Large sources require a later reviewed contract, not a larger hidden buffer. Python's capture/result can coexist briefly; this does not bound a trusted resolver's internal buffering or SQLite/OS memory.

Matching SHA-256 and expected size (when known) establish that returned bytes match the asserted revision, not that the original assertion is authentic or the document's claims true. Checksums are not access grants. Wrong bytes, absent/inaccessible/unavailable sources, budget overflow, malformed reads and close failure never return content. Authorized I/O failures become fixed `SourceExpansionError` codes: `changed`, `missing`, `inaccessible`, `unavailable`, `unverified`, `limit_exceeded`. Policy refusals remain content-free. Locations, payloads and raw resolver/authority errors are not placed in error strings or result reprs. A read-time policy failure is re-raised without retaining the verifier traceback containing a preceding chunk.

## Freshness, Transactions And Cancellation

Before open, each bounded read and release, check the bound effective context, unchanged reader/bank/connection, fresh host source grant and fresh SP1 indexed source authorization. The original metadata/policy identity must still match, allowing only a new read-decision ID. Binding removal, source correction, source restriction, changed grants/epoch or destination/context mismatch therefore stop the next checkpoint and discard the buffer. The grant's resolver/location cannot be replaced midway. No output reaches a model/provider before these checks.

Expansion explicitly refuses an enclosing SQLite transaction rather than hold a caller snapshot across external I/O or commit someone else's transaction. A host needing expansion should supply a dedicated fresh connection, including a supported read-only connection. If a callback starts a transaction, refuse without committing or rolling it back. The existing SP1/S2a/S2b caller-transaction semantics are unchanged. Checkpoints do not hold a database snapshot while performing resolver I/O.

This is cooperative bounded-read cancellation, not linearizable revocation or interruption inside a blocking resolver method. Host resolvers own timeout/cancellation behavior while blocked. Already returned bytes cannot be retracted, and a revocation immediately after the final authorization check remains a caller/host synchronization problem. KeyboardInterrupt/BaseException attempts stream closure and discards the capture. A failed close prevents success, but does not prove a broken resolver released its resource. Buffers/local copies are dereferenced/cleared on exit, not claimed securely wiped. The host remains trusted within the process; arbitrary owner SQL, reflection or malicious callbacks are not sandboxed.

## Storage, Compatibility And Remaining Gates

Original bytes exist only in the explicit transient expansion/result, not in Mnemosyne's database, logs, journal, cache, source catalog or indexes. No default database or schema is created by importing this module or constructing its expander. The result carries source/context/policy provenance, destination, request ID, release decision ID, bytes and verified digest; it is not a reusable capability for another conversation/destination or a promise that a later reopen matches. Consumers must retain these access boundaries and never log payloads by default.

All prior source/policy/recall/adapter implementations remain unchanged; SP2 has no automatic caller. Missing-classification normalization, authorized legacy migration, source project selection, extraction/span expansion, non-original representations, inherited derivative restrictions, revocation propagation, cache/export/sync enforcement, persistent activation, adapter parity and R1 token-budgeted model injection remain open. Unclassified records still need complete explicit access policy; unbound rows do not become public. S3 full-source/retention budgets and S4 resumable indexing are not implemented here. Real resolver confinement and complete P3/P4 cross-path tests are required before protected-mode readiness.

## Qualification Boundary

Use disposable synthetic sources and effective-context authorities. Prove positive bytes as well as denial, exact EOF/budget edges, no second open, changed/missing/offline originals, relocation, wrong/replayed phase/intent grants, participant/grant/binding/source changes, caller transactions, read-only stores, close/cancel failures, forbidden registry/HEAD/presign/provider paths and absence of database payloads. Run the supported interpreter matrix, selected source/policy/adapter regressions, lint/docs and exact-runtime installed artifacts. Retain independent findings, initial failures and corrected evidence separately.

Every legacy implementation remains byte-identical to SP1; that structural observation is not a timing benchmark. No paired performance comparison or formal protected-recall overhead pass is implied. The prior write-tail observation remains open. Source byte access, per-read policy/host checks and payload verification add new explicit work, whose scale/quality/provider integration remains separately unqualified. No GPU energy or semantic-recall improvement is claimed.
