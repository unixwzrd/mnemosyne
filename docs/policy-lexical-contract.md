# P2c: Authorized BEAM Lexical Recall

Status: provisional downstream increment on P2b `bbd0a6890fd3f0fee1755aea9c2c4f9b7fa50eb1`. This adds a usable explicit BEAM retrieval entry point, not protection of ordinary `recall`, hybrid/vector/graph parity, or protected-store activation. Existing calls and adapter defaults remain unchanged.

## Entry Point And Trust

`BeamMemory.recall_authorized_lexical(query, reader=..., destination=..., projects=None, top_k=20, candidate_limit=200)` requires a `PolicyReader` using that exact BEAM connection. Its host-bound context must name the same conversation as `beam.session_id`, declare `recall:lexical` plus the existing bank/project read operation, and pass one fresh trusted verifier decision covering the whole call. Project intent and bank-wide defaults retain P2b semantics; empty selection cannot broaden scope. Constructors and connection identity are not authentication. Real participant intersection, current epochs and destination binding remain host obligations; no production verifier or model-supplied context is added.

Only this entry point declares the LEXICAL surface. Ordinary `recall`, enhanced/polyphonic recall, canonical/fact/graph/media retrieval, vectors, writes, diagnostics, caches, exports and adapters remain unqualified. Unsupported options are not accepted. The new method is read-only: no recall counters, captured query logs, embeddings, source fetches, provider submissions or automatic schema preparation. Existing BEAM construction retains its normal initialization behavior; qualification uses only disposable stores.

## Retrieval Boundary

Reuse the P2a/P2b indexed metadata predicate inside one snapshot spanning both native tiers and content scoring. Materialize authorized metadata first, then apply the existing native session/global, expiry and supersession predicate before any candidate limit. Session scope is deliberately same-session/global (`cross_session=False`) irrespective of an environment override; no new cross-session option is exposed. Other legacy query filters are not implied. Working and episodic FTS tables and their existing mappings must be present; database/capability errors propagate, never become successful empty recall or a broad fallback. Even stopword-only queries validate native content-column mappings and the expected normal/hidden FTS5 columns via structured [table_xinfo metadata](https://www.sqlite.org/pragma.html#pragma_table_xinfo); an ordinary table with a familiar name is not an available FTS surface.

Use BEAM's existing `_fts_query_terms`, precise/exact Hangul term preparation and lexical scorer/gate, not a new query parser. FTS MATCH selects only metadata joined to that eligible relation, without selecting indexed content, snippets, rank or BM25. SQLite's [BM25 corpus statistics](https://www.sqlite.org/fts5.html#the_bm25_function) include all indexed documents: filtering a globally ranked list would not establish ranking over an authorized set. This path therefore never calls that ranker. Private posting lists remain inside the trusted SQLite index; only eligible native identities reach the bounded candidate pool. Modifying denied content can affect internal query timing, which this API does not claim to hide, but not returned scores or the admitted pool.

Preserve exact/precise/expanded query staging, with cumulative thirds/half/full budgets when terms differ. Stage membership is deterministic by native ID, not global BM25 rank; this is not score/order parity with ordinary hybrid recall. Deduplicate native identities before limits. An additional authorized-only probe row signals candidate overflow. Denied, expired, superseded, other-session and irrelevant-project rows cannot consume slots. No LIKE, CJK, Cyrillic, recent-memory, vector or model fallback is invoked. Queries requiring a fallback because they generate no index terms explicitly refuse; stopword-only queries return empty after authorization and schema checks. Indexed non-Latin queries use the same native term preparation, without a promise of fallback completeness.

Fetch native text only for admitted identities, still joined to the materialized eligible relation within the same snapshot. Score only authorized content with the existing lexical scorer and positive relevance gate; technical literal-flag collision checks are reused. Use chunks of at most 64 IDs to fit the 900-label grant budget plus fixed parameters within SQLite's historical variable limit. The pool is bounded per tier (1..1000), `top_k` is 1..100 and no greater than the pool. Query input is bounded nonblank text up to 4096 characters and at most 128 expanded terms. Native memories over 16,384 characters cause a content-free resource-limit refusal without materializing the whole value in Python. This is a prototype scoring bound, not S3's source-retention contract. Non-text or embedded-NUL native content refuses as incompatible, without returning it to Python: [SQLite text length stops at NUL](https://www.sqlite.org/lang_corefunc.html#length), so the SQL CASE explicitly excludes NUL-bearing content before relying on that length. Native storage is not stripped or rewritten.

## Results And Limits

Return immutable `AuthorizedLexicalRecall` with immutable scored `AuthorizedLexicalHit` entries, the per-tier candidate limit, authorized candidates examined, and whether an executed matching stage exceeded its budget (`truncated`). A stage skipped because an earlier stage filled the pool is not probed for overflow; `truncated=False` is never an exhaustiveness certificate. Each hit retains the P2a context/decision/binding/version provenance. Text returned to the caller uses the existing BEAM content cap and an explicit `content_truncated` flag; native storage remains unchanged and scoring uses the full admitted text within the scoring bound. Do not infer completeness from an empty bounded pool or silently expand it. Scores are deterministic lexical relevance, not semantic confidence or fact verification. No denied counts, other project memberships, raw queries or external source text are included.

Existing caller snapshots are preserved, not refreshed. The inherited persistent-cancellation/cleanup limitation remains: errors propagate and connection-owner recovery can be necessary if cancellation also prevents cleanup. No caller handler is cleared by this path. P3/P4 must qualify revocation and every lifecycle/transport surface before activation. S source revision/expansion contracts remain separate.

Qualification uses actual disposable BeamMemory initialization, real FTS triggers/indexes, old-recall regressions, independently calculated authorized candidate/result oracles, high-volume denied distractors, content/scoring/provider tripwires, native scoping, staged queries, explicit failure/overflow behavior, snapshots, cancellation, interpreter and installed-artifact checks. Compare the preceding accepted checkpoint and the new bounded workload without claiming a formal overhead budget, full protected BEAM parity, upstream acceptance or deployment.
