# Source Integrity And Optional Policy-Aware Memory

This is the downstream contribution roadmap for the `unixwzrd/mnemosyne` fork. It describes work in progress, not an upstream release or a deployment recommendation. Existing Mnemosyne behavior remains the default. There is no switch that safely turns the whole system into protected mode yet.

## What We Are Building

Keep original documents and media in their existing authoritative repositories. Mnemosyne should retain compact memories, bounded evidence, search indexes and references to those originals, with revision/checksum lineage so a changed, moved or unavailable source is not mistaken for the evidence originally indexed. Ordinary recall should not fetch source documents. Authorized expansion is a separate, explicit operation.

Make per-memory policy optional and deployment-defined rather than requiring a government classification scheme, cloud service or central authorization server. Where policy is enabled, the trusted host supplies authenticated context and the retrieval engine enforces indexed access constraints before candidate limits or content disclosure. Policy cannot be trusted merely because a model supplied it. Derived facts, vectors, summaries, caches, exports and maintenance operations must retain applicable restrictions before protected operation is offered.

The immediate use cases are assistants with separate general/private contexts, several projects referencing the same evidence, and archive-backed research that must retain provenance without copying whole documents into memory. A common topic or project membership is not permission to disclose information.

## Source And Policy Integration

SP1 adds [immutable source-revision policy associations and authorized metadata reads](source-policy-contract.md). Source metadata needs its own policy binding; citing a source from a memory or authorizing an earlier revision grants nothing to the current source. Both `read:bank` and `read:source-revision` are required, and an eligibility-first indexed query precedes native source metadata. The result omits original bytes, locators and unapproved ancestry. Protected project-selected source access and generic source enumeration refuse rather than silently fall back. This is the prerequisite metadata boundary, not completion of authorized exact-byte expansion.

The corrected SP1 runtime is `3cd219e8ef961ce7d20f48951b9020764122c772`; the initial `806896d` artifact is superseded. Independent review identified join-order/schema, oversized-field error, native text-contract and parent-schema defects, which have dedicated regression controls. Source/asset layouts now require native physical tables with binary keys, an eligibility-first CROSS JOIN enforces the documented SQLite loop order, native-valid representation text remains unchanged and corrupt-metadata errors are content-free. Qualification results and the final independent recheck are recorded in the downstream ledger, not inferred from the existence of these fixes.

At the corrected runtime, 1,148 selected source/policy/media/Hermes-provider regressions pass with two explicit uninstalled-Hermes-loader skips. ## Authorized Source Bytes

SP2 adds the explicit [authorized exact-byte expansion seam](source-expansion-contract.md), depending on SP1 `f154dea`. It requires the additional `expand:source-revision` operation and a fresh trusted host grant bound to request/context/source/destination/budget and phase. One host-approved resolver open supplies the exact builtin bytes hashed by the existing verifier; no second open supplies the response. Policy and host authority are rechecked before open, every bounded read and release. No partial output, source-byte persistence, registry fallback, automatic tool/provider integration or protected activation is added. Caller-owned transactions refuse rather than span external I/O. The host remains responsible for real resolver confinement and timeouts.

Corrected runtime `ce598fa3f1bbab3d20ec49839ef3e0f3f857f094` closes an independent review finding in initial `ee923f3`: after a successful chunk, cancellation could retain plaintext through verifier traceback locals despite outer-buffer cleanup. All six original cancellation probes now pass, alongside 14 focused independent recheck cases. The initial artifact and historical finding remain separately retained and superseded.

## S3a Bounded Admission Boundary

[The indexing contract](source-indexing-contract.md) now fixes conservative candidate limits before introducing a persistent writer. The explicit `plan_source_index` helper validates exact Unicode spans against an extraction digest, external output reference, per-excerpt and complete-plan UTF-8 budgets, a count cap and a fixed 25% retained-text ceiling. It rejects oversized selections and unsupported full-source search rather than truncating or silently claiming coverage. Defaults are 1 KiB per excerpt, 8 KiB and 32 excerpts per plan; explicit hard maxima are 4 KiB / 32 KiB / 128. The transient extraction cap is 8 MiB. These are downstream candidate defaults, not upstream-approved or measured recall-quality optima.

Admission performs no source fetch, provider call, embedding, persistence or legacy-path change. The result is not authorization or an aggregate lifetime-retention receipt. S3 remains partial: a durable writer must account for aliases, revisions, retries, duplicated moment/working-memory/FTS text and sidecars before B1 can pass. Ordinary media ingestion remains unbounded and must not be presented as protected indexing. No activation, migration or live deployment is enabled.

The qualified runtime is `5ddea748fdf0889ac7fb7170c7ed4717cbbdb02e`, depending on SP2 `376ca30`. All 110 new cases pass on Python 3.10-3.14; the selected combined suite passes 1,327 with two unavailable Hermes-loader skips, and the unchanged adapter suite passes 759 with one pinned-host skip. Initial runtime `076050b` accepted malformed URI components; independent review found that defect, and the correction now passes 97 independent URI assertions plus 54 selected pytest cases with no remaining actionable finding in the recheck. The original review's 46 budget/digest/offset probe groups and 22 selected cases remain separately recorded, not claimed as a new full-suite run.

Exact-runtime core/adapter wheels pass PyYAML-only installed-target controls without source checkouts, including 157 RECORD hashes, earlier SP1/SP2 checks and new malformed-reference refusals. Core wheel SHA-256 `95260da435be3e4d5e1630d1e98f9c8972348f03cdd895de6adaf45f40b957c9`; adapter `0fb59da2149bd10f54844cd59abf90e1dca91aa91c97e873b2de593cb4c434f1`. ## S3b Durable Owner-Mode Excerpts

[The durable catalogue contract](source-index-store-contract.md) adds atomic persistent excerpt plans and group-wide logical byte/count limits across registered aliases, byte revisions and retries. An exact retry has no extra charge; new revisions cannot raise the retained-text ceiling. Registration creates fresh native reference-only document assets and refuses adoption of pre-existing ones. Known legacy text, corrupt records, unsupported schema and non-UTF-8 databases refuse explicitly. Original documents and complete extractions remain external; no working-memory, FTS, embedding, provider or automatic adapter path is added.

Qualified source `c6ad7f09753be6e816038a66955c5aaa25a15257` has 83 new store cases plus 110 admission cases, the declared Python 3.10-3.14 matrix, 1,410 selected regressions, 759 adapter cases and an exact-artifact installed-target check. Explicit skips and two independent findings/corrections remain recorded in the contract and contribution ledger. Final independent recheck passes 69 controls without remaining findings in its scoped owner-mode boundary. Development artifacts are not deployed or upstream accepted.

Logical catalogue accounting does not constrain arbitrary legacy writers, dishonest host alias assertions, physical SQLite journal copies or a database-owning process. Policy inheritance, revocation, protected adapters and usable index generations still need their own acceptance. This is progress on S3, not permission to activate protected indexing or a claim that B1 is complete across every enabled surface.

| R1 | Compact token-budgeted evidence recall and authorized expansion, measuring fidelity as well as token savings |

Performance changes are separate, profile-backed contributions, not speculative refactors bundled with schema or security work. Every runtime increment is compared with its preceding checkpoint using synthetic sources and disposable stores. Measures include correctness/authorized recall quality, latency, throughput, memory/index growth, embedding calls and injected tokens where the increment supports them. Small offline lexical timings do not establish semantic recall quality or an overall protected-mode overhead budget.

## Compatibility And Review

Legacy reads/writes are unchanged by default. Prepared metadata and explicit prototype APIs do not protect old entry points against bypass. The application/process owning the SQLite connection remains trusted; this is not a sandbox against arbitrary in-process SQL. Existing callers keep their transactions and snapshots, so request-start verification is not a promise of linearizable revocation.

Contributions remain on focused fork topic branches while upstream architecture and CLA questions are resolved. Maintainer acceptance, an upstream merge, a release and live deployment are separate gates. We do not claim upstream endorsement or production readiness. Existing source, models, original documents, private stores and embedding identities are not migrated by this contribution work.
