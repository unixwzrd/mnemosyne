# P3a: Metadata Inheritance And Classification Normalization

This explicit additive contract begins P3; it does not complete derivative lifecycle. Existing policies, binding schema, readers, writers, sources, adapters and legacy defaults are unchanged. There is no migration, activation, policy service or provider dependency. Helpers accept only bounded, host-supplied metadata; constructing their inputs or result is not authentication or authorization.

## Interfaces And Defaults

`normalize_classification(definition, classification=None, *, inherited=())` returns a sensitivity label and its `explicit`, `inherited` or `default` origin. An absent label with no inheritance becomes exactly `unclassified` only if the deployment vocabulary defines it. A custom vocabulary without that label refuses instead of substituting its least-restricted label. Unknown, empty or malformed explicit/inherited values refuse; they never default. A stricter trusted inherited label always wins. The result grants no audiences, purposes, owners, compartments or access. No existing row is changed and no migration automatically applies the default. Persisting origin and previewable legacy migration remain later work.

`derive_memory_policy(definition, parents)` accepts 1..128 explicit `PolicyParent(reference, policy)` records. References must uniquely identify exact trusted supporting binding/revision metadata, not titles or model assertions. The pure result includes the complete immutable parent metadata sorted by reference, the derived MemoryPolicy and a deterministic SHA-256 fingerprint over both. A hash is neither anonymization nor a source-verification receipt. No original memory/document content is accepted or stored.

The derived label is the highest parent classification; required compartments and overlays are unions; audiences and purposes are intersections. Empty intersections remain empty and denied rather than becoming wildcards. Unsupported overlays remain present so an incapable reader refuses. Current native metadata can express only one owner and tenant, so differing owners/tenants refuse rather than selecting one or dropping a tenant requirement. Cumulative requirement labels must still fit MemoryPolicy's existing bounds; excess refuses without truncation. All parents must match the exact deployment vocabulary/version. No authorized declassification or cross-owner merge API is supplied.

The derived policy uses existing `classification_source=external`: its immediate source is this explicit external inheritance calculation, not a fabricated human decision or single originating conversation. A shared origin context/epoch is preserved only when every parent agrees; otherwise the result has no single origin, while every original context/epoch remains in the parent receipt. The result must be persisted with that lineage by a future atomic derivative writer; using only its MemoryPolicy is not lifecycle-complete protected ingestion.

## Enforcement And Completion Boundary

The host is responsible for supplying every applicable supporting parent, freshly verifying their restrictions, authorizing any compute/provider use, and withholding derived content until publication is authorized. These helpers cannot detect omitted parents or establish authenticated participant intersection. P3 still needs durable provenance edges, source/parent correction and revocation quarantine, indexed descendant exclusion before candidate consumers, cache/handle invalidation, maintenance/export/sync restrictions and content-free audit. P4 must gate adapters/activation; older ordinary paths are not protected by this contribution. Standalone pure metadata tests are not evidence that summaries, native embeddings, caches or handoffs already inherit these rules.

Qualification uses synthetic metadata, a bounded classification/permission lattice, malformed and unsupported combinations, deterministic identity, origin preservation, empty intersections and immutable caller inputs. Schema upgrade/interruption/recovery and live migration do not apply to this no-schema increment; they remain mandatory before any later persisted lifecycle feature. Runtime costs are compared on identical bounded inputs; no model recall quality or system-wide performance budget is claimed from a pure helper. No upstream changelog is modified.
