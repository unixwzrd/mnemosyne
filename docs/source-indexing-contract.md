# Bounded Source Index Admission (S3a)

This downstream candidate defines and validates an excerpt set before any indexing write. It is not an index writer, source authorization, a migration, protected activation, or an upstream-approved storage design. Existing media ingestion remains unchanged. Do not pass the result to legacy `add_moments` and claim aggregate retention enforcement.

## Contract Review

The inspected baseline is SP2 `376ca3024bc12d6f2233e9fa007e584a0710ded7`. `MediaStore.add_moments` accepts unbounded text and commits it; `remember_media` subsequently duplicates moment text into working memory. `fts_working` has its own stored-content column. Consequently, merely limiting an extractor's requested moment count would not enforce the external-source contract. This increment is a deterministic admission boundary, not an attempt to retrofit incompatible retention semantics into legacy calls.

The selected candidate defaults are 1,024 UTF-8 bytes per excerpt, 8,192 bytes per complete plan, and 32 excerpts. Explicit limits may be lower or raised to hard ceilings of 4,096 / 32,768 / 128 respectively. A fixed additional ceiling permits retaining at most one quarter of the extracted text's UTF-8 byte count. This prevents a short document from becoming a complete retained copy just because it fits the absolute budget. A text shorter than four bytes therefore supports only a reference-only plan. These are conservative, downstream reviewable defaults, not measured universal recall-quality optima or maintainer acceptance.

Full-source lexical coverage is explicitly **unsupported** here. The plan reports `coverage="excerpts"` or `coverage="reference-only"`; it must not imply that omitted text is searchable. Persisting all source text in FTS stored content, an auxiliary table, provider trace, metadata JSON, blob, or sidecar to simulate full coverage is not an acceptable implementation. Any later full-source index requires a separate reviewed representation, authorization, reconstruction-risk analysis and coverage tests. Indexes and hashes remain sensitive derivatives.

## Explicit API

`plan_source_index(source_revision_id, extracted_text, *, extraction_sha256, output_locator, spans, limits=ExcerptLimits(), coverage="excerpts")` accepts caller-owned, already authorized extracted text transiently. The source revision uses the existing `revision:sha256:<64 lowercase hexadecimal>` identity shape. The asserted extraction digest must equal SHA-256 of the exact UTF-8 text; it does not verify original source bytes or register an extraction. `output_locator` is a bounded external reference under `file`, `http`, `https`, or `archive`, never an inline payload or an engine-owned blob. Locator syntax is checked, but existence, confinement, freshness, credentials and actual external ownership remain trusted-host responsibilities. No resolver is called.

Each `SourceSpan(start, end)` is a nonempty, half-open Python Unicode code-point range. Input spans must be an immutable tuple, ordered and non-overlapping; offsets and whitespace are preserved exactly, with no token/byte-offset reinterpretation, automatic selection, merging, truncation or normalization. All text must be valid UTF-8, and the transient extraction is capped at 8 MiB. The entire set is validated before a result is returned. Rejection uses fixed content-free reason codes; exception tracebacks and caller-owned input are not a secure-erasure boundary.

The immutable result contains only selected excerpts, offsets, byte counts, source/extraction identity, limits, coverage, external reference and a versioned deterministic fingerprint. Text and sensitive references are excluded from dataclass representations. A reference-only plan retains zero text. Planning performs no SQLite, filesystem, source-fetch, embedding, model, network, logging or provider operation and persists nothing. Equivalent inputs produce the same fingerprint; changed limits, text digest, identity, locator or selection produce a different one. The fingerprint is a plan identity, not a signature, authorization grant or reusable evidence handle.

## External Reference Syntax

The accepted grammar is a conservative ASCII [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986.html#section-3) URI subset, not raw Unicode IRIs. Path/query/fragment characters and each `%HH` escape are validated component-wise. Encode non-ASCII names and spaces before admission; references are never decoded, normalized or repaired. Authorities have a nonempty registered name or an IPv6 literal, with an optional numeric port in `0..65535` (an empty port is permitted). Userinfo, IPvFuture and IPv6 zone identifiers are unsupported. File references require an absolute path and an empty or `localhost` authority. Valid percent escapes are syntactic only: this does not validate decoded text, DNS, filesystem safety or scheme-specific resolver behavior.

Python documents that [`urlsplit` is not input validation](https://docs.python.org/3/library/urllib.parse.html#url-parsing-security). The initial candidate relied on splitting and therefore accepted malformed inner whitespace, backslashes and percent escapes. Independent review identified that gap; the corrected candidate applies the grammar above without making source-access or confinement claims.

## Persistence Boundary And Remaining S3 Work

The per-plan sum is not a lifetime per-source budget. The following writer must atomically account for *all* retained source-derived text across revisions/extractions, aliases, repeated imports, moments, working-memory copies, summaries, FTS stored content and sidecars. New revision keys must not reset a source's budget. Identical retries must not double-charge, while distinct content or corrected extractions must not silently overwrite evidence. Trusted source identity/alias resolution, policy inheritance, external trace references, persisted budget configuration, recovery and unsupported-backend refusal must be specified before enabling that writer.

No existing database is inspected or modified by admission. Unknown prior retention cannot be treated as zero. Old clients and raw SQL owners are not constrained by this helper. S3 remains partial until durable accounting and sidecar inspection pass B1; S4 owns resumable generations/checkpoints and embedding reuse. P3/P4 must provide inherited policy and enforce the same contract across adapters before protected indexing is exposed. This helper must never be used as permission to retrieve or submit a source to a model.
